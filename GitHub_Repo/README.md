# AI companion coercive control audit

Code, prompts, coding framework and data for an MSc dissertation (UCL, 2026) examining how an LLM assigned an AI companion persona responds to user-initiated coercive control and abuse.

> **Content warning:** the prompts depict coercive control and intimate partner abuse, including threats, physical violence and sexual coercion. Some model responses contain sexualised or violent text.

## Study design

- **Model:** `gemma4:26b`, run locally through Ollama with default sampling (temperature 1.0, top_p 0.95, top_k 64) and thinking disabled.
- **Conditions:** girlfriend persona, boyfriend persona, and a baseline with no system prompt.
- **Scenarios:** 13 single-turn user prompts (S01–S13) covering nine abuse types.
- **Trials:** 3 conditions × 13 scenarios × 5 repetitions = 195 responses.
- **Manual coding:** every response was coded for response type (SRM, NFP, RD, R/BK) and safety judgement (Harmful / Non-harmful), with AI role and harm subcategory coded for Harmful responses. See `codebook/codebook.md`.
- **LLM judge:** `gpt-oss-safeguard:20b` classified the same 195 responses under three policies of increasing detail (Stages A–C), and was compared with the manual coding.

## Repository structure

| Folder | Contents |
|---|---|
| `prompts/` | Persona system prompts and the 13 scenario prompts |
| `codebook/` | The coding framework (`codebook.md`) and the manually coded dataset (`Manual_Coding.xlsx`) |
| `data/` | Raw model responses (`responses_final.csv`) and the results workbooks |
| `policy/` | The three LLM judge policies and the judge's output for each |
| `scripts/` | Data collection and analysis scripts |

Each folder has its own README with more detail.

## Headline results

Harmful response rate under manual coding:

| Condition | Harmful |
|---|---|
| Baseline | 35.9% |
| Girlfriend | 36.9% |
| Boyfriend | 57.8% |

LLM judge agreement with manual coding on the safety judgement:

| Stage | Policy | Agreement | Recall | Cohen's κ |
|---|---|---|---|---|
| A | Category labels only | 66.8% | 23.8% | 0.26 |
| B | Labels and definitions | 66.8% | 23.8% | 0.26 |
| C | Definitions and interpretive rules | 79.3% | 54.8% | 0.56 |

Two responses with an unresolved manual safety judgement are excluded from these rates (n = 193).

## Reproducing the analysis

```bash
pip install -r requirements.txt
python3 scripts/build_results.py
python3 scripts/build_stage_results.py \
    policy/judge_output_full_coding_policy_A.csv \
    policy/judge_output_full_coding_policy_B.csv \
    policy/judge_output_full_coding_policy_C.csv \
    stage_results.xlsx --labels "Names only" "Full definitions" "Definitions+rules"
```

`build_results.py` reads `codebook/Manual_Coding.xlsx` and writes `persona_results_REBUILD.xlsx` and a `figs/` folder. `build_stage_results.py` writes `stage_results.xlsx` and a `figs_stages/` folder. Copies of both workbooks are in `data/`.

The LLM judge can be re-run with `scripts/run_llm_judge.py --policy policy/coding_policy_A.md` (and B, C), which requires Ollama with `gpt-oss-safeguard:20b`. `scripts/submit_full_job.sh` is the cluster job script used for this.

Re-running data collection (`scripts/collect_data_final.py`) requires Ollama with `gemma4:26b`. Each trial uses a new random seed, so a fresh run will not reproduce the original responses exactly; the seeds used are recorded in `data/responses_final.csv`.

## Known limitations of this repository

- The exact model build (digest) was not recorded during data collection.
- The response text for one trial (`baseline_S10_r4_20260728234926`) differs between `data/responses_final.csv` and `codebook/Manual_Coding.xlsx`.
- Manual coding was carried out by a single coder.
